## 요약

이 시트는 이미 장도초의 온라인 교무실 역할을 하고 있습니다. 새 온라인 교무실의 핵심은 같은 내용을 한 번만 입력해 여러 화면에 쓰고, 비밀번호·학생 정보 노출을 막는 것입니다.

- **분석 범위**: 시트 18개(업무 자료 2, 학사일정 1, 월별 계획 12, 특별실 시간표 1, 폐기 조사 1, 방학 봉사자 1), 칸에 걸린 링크 46개(중복 빼면 34곳: 구글 문서·파일 25, 외부 사이트 9)

- **가장 큰 문제 세 가지**

  - 같은 정보를 여러 곳에 따로 입력: 행사, 방학 근무자, 교직원 명단

  - 조사·신청을 공유 시트 탭으로 받아 미제출자·마감을 사람이 직접 챙김

  - 계정 비밀번호와 학생 계정·배경 정보가 공유 문서에 그대로 있고, 원본 시트는 로그인 없이 링크로 열림

- **필요 기능**: 11개 영역 49개(필수 18 · 권장 26 · 선택 5). 지금 시트에서 하는 일 34개, 새로 제안하는 일 15개

- **1차 오픈 범위(확정)**: 공통 계정 로그인·권한, 홈(오늘·이번 주), 학사·월별 일정(부서가 입력하면 자동 취합), 업무 자료실·도움말, 교직원 명단, 조사·신청과 제출 현황(필수 15개)

- **확정 사항**: 구글 시트를 데이터 창고로 쓰는 웹앱(데이터는 새 전용 시트에 저장, 원본 시트는 그대로), 공통 계정으로 시작(제출할 때 이름과 개인 번호 4자리로 본인 확인, 개인 계정은 나중에 추가·수정), 관리는 연구부장 1명(보완안: 부담당 1명)·입력은 전 교직원, 학사일정은 엑셀 목록 양식으로 한 번에 올리기, 봉봉클래스의 학급 배정·전담시간표 작성 기능은 일단 제외

- **확인 필요**: 링크 34곳 중 학교제규정 파일은 열리지 않고, 교육청 누리집 3곳은 화면 내용을 읽지 못함. 시트 안 숫자·표기 몇 가지는 '확인이 필요한 사항'에 정리

## 지금 방식의 문제점

문제의 뿌리는 누구나 편집하는 공유 시트에 같은 정보를 여러 번 적는 구조입니다. 시트 전반에서 아래 여섯 가지가 반복됩니다.

> **그림 · 반복 입력 구조 (사례 3가지)** — 같은 정보가 두세 곳에 따로 입력돼요(원본 시트와 연결 문서에서 확인한 사례).
>
> - 학교 행사(예: 4월 30일 운동회) → 2026.학사일정, 월별 계획 시트
> - 방학 중 근무자(2025·2026학년도) → 25.방학봉사자, 7·8·1월 시트의 관리자 근무 열
> - 교직원 명단(조사마다 새로 작성) → 전학공 참여 여부, 생일경비 희망조사, 법정연수 기록
> - 바꿀 방향(온라인 교무실): 한 번 입력하면 일정·명단·근무표 화면에 함께 표시

세 사례 모두 한 곳에서 입력하고 여러 화면이 같은 내용을 가져다 쓰면 해결됩니다.

1.  **반복 입력**: 행사는 학사일정과 월별 계획에, 방학 근무자는 방학봉사자 시트와 7·8·1월 '관리자 근무' 열에 따로 적음. 교직원 명단은 조사마다 새로 만듦

2.  **조사·신청이 탭으로 늘어남**: 동료장학·전학공·멘토링·생일경비·참석 여부를 시트 탭으로 받음. 미제출자와 마감은 사람이 직접 확인하고, 남의 칸을 덮어쓸 위험이 있음

3.  **찾기 어려움**: 표시 이름이 업무와 다르고(예: '문화체육부'), 2025·2026 자료가 섞이며, 검색·필터·수정일이 없음. 부서명도 시트마다 다름(복지부·교육복지부, 체육부·문화체육부, 정보부·정보과학부)

4.  **민감정보 노출**: 계정 정보(비밀번호·검증번호) 평문 2건, 학생 계정·학생 배경 정보 문서로 바로 연결, 비상연락망 파일 링크. 원본 시트도 로그인 없이 링크로 열림

5.  **해마다 복제**: 새 학년도에 시트를 복제해 지난 학년도 표기가 남음(예: 12월 '2025학년도 학교생활기록부 기재요령')

6.  **숫자 관리**: 목적사업비의 지출·남은 예산 칸이 비어 있음. 시트 합계 101,945,000원은 행별 합 118,145,000원보다 16,200,000원 적은데, 한 칸에 금액 두 개를 적은 두 사업(지역연계교육과정, 1인 1예체능)이 합계에서 빠진 것으로 보임(확인 필요)

## 단계별 구축 범위

1차는 필수 기능 15개로 매일 쓰는 화면과 조사·신청을 함께 열고(확정), 사용이 자리 잡으면 배정과 기록·예산 기능을 차례로 붙이는 순서를 제안합니다.

> **그림 · 구축 순서 (3단계)** — 매일 쓰는 기본과 조사·신청부터 열고, 배정·기록은 차례로 붙여요(1차 범위는 확정, 2·3차 순서와 넘어가는 시점은 제안).
>
> - **1차 · 기본과 조사·신청(필수 15개, 확정)**: 로그인·권한·휴대폰 화면 / 홈: 오늘·이번 주 일정 / 학사·월별 일정, 부서 입력 / 업무 자료실·검색·보관 / 도움말: 복무·인사, 제규정 / 교직원 명단·내선 / 조사·신청 양식·제출 현황
> - **2차 · 취합과 배정(필수 3개와 권장)** — 교직원이 매일 쓰기 시작하면: 조사 응답 자동 집계 / 특별실 시간표·예약 / 방학 근무·보결 배정 / 법정연수 이수 확인 / 공지·할 일 알림 / 시설 요청·기기 대여
> - **3차 · 기록과 예산(권장·선택)** — 한 학기 운영을 점검한 뒤: 업무 계획·반성 기록 / 협의회 안건·회의록 / 전학공·동료장학 기록 / 목적사업비 집행 현황 / 외부강사·체험 기록 / 캘린더 구독·공문 기한

2차의 필수 3개는 특별실 시간표, 방학 근무 배정, 법정연수 이수 확인입니다. 1차의 조사·신청은 공통 계정에서도 누가 냈는지 알 수 있게, 제출할 때 교직원 명단에서 이름을 고르고 개인 번호 4자리를 넣는 방식으로 만듭니다.

## 보안·개인정보 원칙

온라인 교무실은 안내·일정·취합을 맡고, 학생 개인정보와 계정 정보는 올리지 않는 것을 원칙으로 제안합니다. 지금 시트에서 가장 급한 부분이기도 합니다.

- **접근**: 공통 계정으로 로그인해야 열람. '링크가 있는 모든 사용자' 공개는 쓰지 않음. 공통 계정 비밀번호는 시트·화면에 적지 않고 웹앱 설정에만 두며, 교직원이 바뀌는 학기 초에 바꿈

- **본인 확인**: 공통 계정으로 들어와도 응답·입력할 때 이름을 고르고 개인 번호 4자리를 넣음. '이 기기에서 기억하기'는 개인 휴대폰에서만 켜고, 교무실 공용 PC에서는 끔. 보완안: 번호를 잊으면 연구부장·부담당이 다시 정해 주고, 여러 번 틀리면 잠시 잠금

- **전출·휴직자**: 계정 표에서 '사용 안 함'으로 바꿔 이름 목록과 알림에서 빠지게 함

- **관리자 권한**: 계정 추가·수정, 메뉴, 학년도 전환, 공지는 연구부장과 부담당 1명만. 관리자 화면은 공통 계정과 다른 비밀번호로 들어감

- **계정 정보**: 비밀번호·검증번호는 어떤 화면에도 적지 않음. 공용 계정은 담당자에게 따로 받는 방식

- **학생 정보**: 학생 계정, 학생 배경(북한배경·다문화 등), 학생 명단은 교무실에 올리지 않고 원본 문서 권한으로 관리. 교무실에는 '어디서 받는지'만 안내

- **교직원 연락처**: 비상연락망은 권한 있는 사람만 보고, 내려받기 제한

- **관리자 근무**: 부재·출장만 표시하고 사유(병가 등)는 쓰지 않음

- **기록**: 수정 이력을 남기고(공통 계정 동안은 입력자가 고른 이름으로), 학년도가 끝나면 보관함으로 옮김

- **구축 전에라도**: 원본 시트의 공유 범위 확인, 시트에 적힌 비밀번호(학교사진 원드라이브의 공용 O365 계정 포함) 변경·삭제를 원본 소유 선생님께 먼저 요청

## 확정 사항과 다음 단계

디자인 전에 정할 네 가지가 모두 정해졌고, 참고 사이트 기능은 일단 빼고, 학사일정은 엑셀로 한 번에 올리기로 했습니다. '보완안'은 확정 사항을 지키면서 생기는 빈틈을 메우는 제안입니다.

1.  **1차 범위**: 조사·신청까지 넣어 필수 기능 15개로 연다

2.  **만드는 방식**: 구글 시트를 데이터 창고로 쓰고 화면은 웹앱으로 만든다. 지금 자료가 모두 구글 시트·드라이브에 있어 옮기는 일이 적음. 데이터는 새로 만든 전용 시트에 저장하고, 다른 선생님 소유인 원본 시트는 건드리지 않는다

3.  **로그인 계정**: 일단 공통 계정 하나로 쓰고, 나중에 개인 계정을 추가·수정할 수 있게 한다. 보완안: 누가 냈는지는 제출할 때 교직원 명단에서 이름을 고르고 개인 번호 4자리를 넣어 남기고, 처음부터 계정 표(이름·역할·사용 여부)를 두어 개인 계정으로 넘어가기 쉽게 함

4.  **관리 주체**: 연구부장 1명이 계정·메뉴·학년도 전환·공지를 관리하고, 일정 입력과 조사 응답은 전 교직원이 한다. 보완안: 관리자 화면은 공통 계정과 다른 비밀번호로 들어가고, 연구부장이 자리를 비울 때를 대비해 부담당 1명을 둠

5.  **참고 사이트 기능**: 봉봉클래스의 학급 배정·전담시간표 작성 기능은 복잡해질 수 있어 일단 빼고 진행한다

6.  **학사일정 올리기**: 엑셀 목록 양식(시작일·끝일·행사명·대상·담당 부서·구분)으로 한 번에 올리고, 미리보기에서 확인한 뒤 반영한다. 올린 묶음은 되돌릴 수 있고, 부서가 직접 입력한 행사는 지우지 않음. 지금의 달력 모양 학사일정은 처음 한 번만 목록 양식으로 바꿈(원본 소유 선생님 동의 뒤). 우선순위는 권장으로 두었고, 1차 범위에 넣을지는 확인 필요

다음은 네 가지이고, 1번은 끝났습니다.

1.  **참고 사이트 확인**: 끝남. 두 기능 모두 만들 수는 있지만 복잡해져서 일단 빼기로 함(확정 사항 5번)

2.  **공통 계정 운영**: 비밀번호를 교직원에게 알리는 방법과 바꾸는 시기를 연구부장이 정함

3.  **화면 설계**: 홈·일정·조사·신청 시안(PC·휴대폰)과 조사 응답(PC)·학사일정 엑셀 올리기 화면을 만듦. 남은 화면은 자료실·교직원 명단·도움말·운영 안내서

4.  **관리자 화면 시안**: 계정 표(이름·역할·사용 여부), 개인 번호 다시 정하기, 학년도 전환 화면을 다음 시안으로 그림. 개인 번호 방식을 운영하려면 꼭 필요함
